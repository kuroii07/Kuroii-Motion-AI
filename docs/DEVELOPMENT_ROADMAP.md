# Kuroii Motion AI 开发路线

本文是从当前 `0.5.9-alpha.0` 可接续开发的工作路线。每一阶段完成后都应运行对应 smoke tests；涉及 AE / PR 的真实宿主操作只在用户明确同意并手动验收后进行。

## 当前基线

- Provider Hub V2：命名配置、能力绑定、Windows DPAPI 密钥存储与真实模型刷新。
- 内容生成：文案会话、图片真实生成与本地历史；视频具备异步提交、轮询、历史和下载入口，但需要绑定真实视频模型后才会调用。
- Desktop Prototype：深浅主题、侧栏、内容工作区、专业模式、视觉验收与本地服务健康检查。
- Local Service：localhost-only、会话令牌、脱敏日志和只读宿主动作边界。

## 阶段 1：视频生成闭环

目标：让现有视频页面能稳定接入一个真实视频供应商，而不是停留在通用协议层。

1. 在 Provider Hub 添加并测试视频模型配置：提交路径、状态路径、模型能力标签与默认绑定。
2. 以一个真实供应商完成一次端到端任务：提交、排队、轮询、完成预览、下载与刷新后恢复历史。
3. 增加供应商差异映射：参考图、首尾帧、负面提示、种子、批量/队列与取消能力，仅展示实际支持的字段。
4. 将失败原因细分为配置、额度、超时、内容安全、供应商队列和结果过期，并给出可执行恢复动作。

验收：有真实视频 URL/文件、可回看任务历史、刷新不丢失任务，且任何失败都不会被显示为成功。

## 阶段 2：音乐与配音工作区

目标：补齐音频生产链路，并与 AE / PR 的素材工作流对齐。

1. 音乐生成：提示词、风格参考、任务历史、试听、下载、授权/来源元数据。
2. 配音生成：脚本分段、角色/音色、语言、语速、情绪、试听与 WAV/MP3 导出。
3. 音频资产库：统一管理图片、视频、音乐和配音的来源、提示词、模型、生成时间与可复用参数。
4. 导出到 AE / PR 前保持“仅生成文件/清单”的安全边界，不自动修改宿主工程。

验收：至少各接入一个真实音乐和语音模型；可试听、下载、复用参数并在刷新后恢复历史。

## 阶段 3：创作编排与项目资产流

目标：让文案、分镜、图片、视频与音频成为同一个项目的可追溯资产。

1. 项目级 Brief、镜头列表和素材关联。
2. 从文案/分镜一键创建对应图片、视频、音乐、配音任务草稿。
3. 资产版本、收藏、标签、搜索、失败重试与批量队列。
4. 导出项目包：素材文件、元数据 JSON、提示词、许可证/来源说明。

验收：一个短片项目能从 Brief 追溯到每个镜头、每个素材及其生成参数。

## 阶段 4：AE / PR 受控集成

目标：从当前只读宿主验证进入显式授权、可回滚的写入流程。

1. 先完成真实 AE / PR 手动 smoke：连接、上下文读取、白名单只读动作、日志证据。
2. 增加导入预览与变更计划：展示将导入哪些素材、创建哪些合成/序列，不直接执行。
3. 仅对明确确认的计划执行写入；每次写入保留操作记录和回滚指引。
4. 建立 AE / PR 版本兼容矩阵和安装/更新流程。

验收：真实宿主的导入路径可重复、可审计、可停止，不修改未确认的工程内容。

## 阶段 5：发布准备

1. Tauri/Desktop 发行包、首次启动向导与数据目录隔离。
2. Provider 配置迁移、备份/恢复、密钥安全检查。
3. CI：结构检查、smoke tests、依赖与密钥扫描。
4. 发布说明、安装文档、问题反馈模板和版本策略。

## 下次回家继续时的建议顺序

先完成阶段 1 的真实视频模型接入与一次端到端验收；随后进入音乐生成页，再进入配音页。这样可先验证异步媒体任务模型，再复用同一套任务、历史、下载和资产元数据基础设施。
